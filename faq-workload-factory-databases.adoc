[[getting-started-and-permissions]]
== 入門指南和權限

.什麼是 Workload Factory for Databases，它支援哪些資料庫引擎和部署模型？
Workload Factory for Databases 可探索、評估、配置與管理 FSx for ONTAP 上的 SQL Server、PostgreSQL 和 Oracle 資料庫。

請參閱 link:learn-databases.html["了解資料庫工作負載工廠"] 以了解支援的型號。

.Workload Factory for Databases 在哪些 AWS 區域中可用？
Workload Factory for Databases 可在所有支援 FSx for ONTAP 的商業區域運行，但在中國區域、Secret Cloud 或 Top Secret Cloud 中不可用。

https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/["檢視支援的Amazon地區。"^]

.我是否需要授予 AWS 權限才能開始使用 Workload Factory for Databases？
否。您可以在未授予權限的情況下以基本模式啟動，並從 Codebox 複製部分完成的程式碼範例。如果您想要探索主機並管理資源，則必須新增 AWS 認證資料，並為所需的權限建立 IAM 原則。請參閱 link:quick-start-databases.html["快速入門"]。

.每個工作（探索、註冊、資料庫建立、主機部署、修復組態）需要什麼權限層級？
已偵測主機的節省計算器和錯誤記錄分析器需要檢視、規劃和分析權限。註冊資源、建立資料庫、建立沙箱 Clone 以及修復架構完善的問題需要操作和修復權限。部署新的資料庫主機需要資料庫主機建立權限。

link:https://docs.netapp.com/us-en/workload-setup-admin/permissions-reference.html#permissions-for-database-workloads["資料庫工作負載的權限"^]



[[deploy-database-hosts]]
== 部署資料庫主機

.部署 SQL Server 主機時，「快速建立」和「進階建立」有什麼區別？
快速建立會套用預設值：FCI 部署、Windows Server 2016 和 SQL Server 2019 標準版。進階建立可讓您自訂部署模型（FCI 或單一執行個體）、作業系統、版次、版本、執行個體類型、配置的 IOPS 和處理量、加密與監控。

link:create-database-server.html["建立 SQL Server 主機"]。

.新的 SQL Server FCI 或獨立式部署會建立怎樣的 FSx for ONTAP 組態？
FCI 部署會建立 Multi-AZ FSx for ONTAP 檔案系統，且 FCI 僅支援 Multi-AZ 組態。獨立式部署會建立 Single-AZ 檔案系統。如果您選擇現有的檔案系統，則會為 SQL Server 工作負載建立新的儲存設備 VM。

link:create-database-server.html["建立 SQL Server 主機"]。

.部署主機是否會改變我的 VPC 網路組態？
有可能。部署會建立所需的 AWS 介面端點和 S3 閘道端點（如果它們不存在）。它也會將 VPC DNS 屬性 `EnableDnsSupport` 和 `EnableDnsHostnames` 設為 true（如果尚未設定）。

link:create-database-server.html["了解更多關於建立 SQL Server 主機"]。

.部署 SQL Server 主機需要哪些 Active Directory 存取？
您需要 Active Directory 管理存取權，以便部署能夠參加網域並建立電腦物件。如果您未提供 SQL 服務帳戶，部署將會建立一個。對於使用者代管的 Active Directory，您必須提供一個安全性群組，允許從 EC2 執行個體到目錄服務的流量。

link:create-database-server.html["了解更多關於建立 SQL Server 主機"]。

.為什麼我的 SQL Server 部署會因為 CredSSP 而失敗？
在部署期間，Workload Factory 會啟用 CredSSP，以便將認證資料委派給資源配置指令碼。如果群組原則封鎖所有網域電腦的 CredSSP 委派，部署就會失敗。部署後，Workload Factory 會停用 CredSSP。

link:create-database-server.html["了解更多關於建立 SQL Server 主機"]。

.部署完成後我可以立即連線到 SQL Server 嗎？
不會立即生效。Workload Factory 不會在已部署的 SQL Server 上啟用遠端連線，因此您需要自行設定，例如在安全性群組中允許所需的用戶端 IP 或子網路。

link:create-database-server.html["了解如何在 SQL Server 上啟用遠端連線"]。



[[register-and-manage-resources]]
== 註冊與管理資源

.在 Workload Factory 中註冊執行個體可以獲得什麼好處？需要滿足哪些前提條件？
註冊可讓您建立資料庫和沙箱 Clone、執行錯誤記錄分析，以及最佳化組態。資源必須在 FSx for ONTAP 儲存設備上執行，並顯示在清單中，這需要 AWS 認證資料。您也必須將連結與 FSx for ONTAP 檔案系統建立關聯，並完成先決條件檢查，包括適用於 SQL Server 的 AWS 和 NetApp PowerShell 模組。

link:register-instance.html["註冊資源"]。

.哪些資料庫可以註冊和代管？ PostgreSQL 呢？
只有 SQL Server 執行個體（FCI 和獨立式）以及 Oracle 資料庫才能註冊和管理。PostgreSQL 主機會根據您的 AWS 認證資料出現在清單中，但並未註冊。偵測功能僅涵蓋 Amazon Linux 上的 PostgreSQL 和 Red Hat Enterprise Linux 上的 Oracle。

.在沒有網際網路存取的私有網路中註冊執行個體需要哪些條件？
確保 S3、AWS Systems Manager 和 FSx for ONTAP 的 VPC 端點在 VPC 中可用，並在安全性群組中允許介面端點使用 443 連接埠。如果您使用 Proxy，則也必須允許所需的 Microsoft、PowerShell Gallery（SQL Server）和 AWS 網域。

link:register-instance.html["了解如何註冊資源"]。

.註銷資源時會發生什麼事？
您無法再透過控制台部署或監控該資源，其 FSx for ONTAP 儲存容量也不再計入執行個體已使用容量。您可以稍後重新註冊該資源。

link:deregister-instance.html["註銷資源"]。

.建立資料庫需要了解哪些知識？
建立資料庫會新增兩個具有獨立 LUN 的新 Volume，供資料和記錄檔案使用。這些檔案採用精簡配置，僅使用所配置大小的幾 MB。使用 SMB 的 SQL Server 不支援建立資料庫。

link:create-database.html["建立 SQL Server 資料庫"]。



[[savings-calculator]]
== 節約計算機

.節省成本計算器比較了哪些內容，以及如何評估內部部署 SQL Server 主機？
它會比較 FSx for ONTAP 與 Amazon Elastic Block Store、FSx for Windows File Server 及內部部署儲存設備上的儲存設備、運算、SQL 授權、快照和 Clone 成本。對於內部部署主機，您可以下載 PowerShell 評估指令碼，在主機上執行該指令碼，然後上傳結果。然後，您可以選擇最多五個主機進行分析。請注意，內部部署 Volume 的大小不會計入成本和節省百分比的計算中。

link:explore-savings.html["了解如何使用節省計算機"]。

.為什麼計算機建議將 SQL Server 企業版降級為標準版？
當執行個體的 vCPU 數量為 48 個或更少，且記憶體容量為 128 GB 或更少時，建議降級。此外，執行個體不得使用企業版功能，例如線上索引作業、資源調控器、點對點或 Oracle 複寫、R/Python 擴充功能或記憶體最佳化 TempDB。部署模型也不得需要企業版。

.當我選擇多個主機時，計算器如何決定 FSx for ONTAP 組態的大小？
您可以選擇最多五個偵測到的主機。除非主機超過單一檔案系統的處理量、容量或 IOPS 限制，否則 Workload Factory 會將它們合併到一個包含單一 SQL 執行個體的 FSx for ONTAP 組態建議中。不支援建立或儲存多個 FSx for ONTAP 檔案系統。

link:explore-savings.html["探索節約效益"]。



[[well-architected-configurations]]
== 架構良好的組態

.一次性和持續性的架構完善評估之間有什麼差異？
一次性評估會在主機上執行指令碼並上傳結果，因此無需儲存任何認證資料，也無需註冊資源。持續評估則需要註冊資源、關聯連結並授予權限。它每日進行分析，並能自動修復問題。

link:optimize-configurations.html["最佳化您的資料庫組態"]。

.在修復架構良好的組態問題之前，我應該考慮哪些風險？
某些修復方案可能會導致停機或服務中斷，因此請先仔細審查每項建議。例如，在變更生產環境配置之前，請先測試 RSS 和 MAXDOP 建議的效能。

link:optimize-configurations.html["執行評估以了解更多組態建議"]。

.我可以忽略不適用於我環境的架構完善建議嗎？
是的。忽略組態會停止對其分析，避免不必要的警報，並將其從總最佳化分數中移除。您可以隨時重新啟動它，分析將恢復每日進行。

link:optimize-configurations.html["從架構良好的評估中排除組態"]。

.為什麼最佳實務做法建議停用 SQL Server 和 Oracle 的 Volume 上的排程本機快照？
排程的 FSx for ONTAP 快照不具備應用程式一致性。建議使用 NetApp SnapCenter 等工具從外部管理快照，以取得應用程式一致的備份，並避免在還原期間發生毀損。請注意，進階建立主機部署預設會啟用具有 7 天保留期的每日快照原則。

link:optimize-overview.html["深入瞭解資料庫組態的分析"]。



[[sandbox-clones]]
== 沙盒 Clone

.如何建立沙盒 Clone，以及可以將其放置在何處？
沙箱 Clone 是從來源資料庫的最新快照建立。它可以位於同一個 SQL Server 執行個體或另一個執行個體上，只要目標主機與來源位於同一個 VPC 中，並且共用相同的 FSx for ONTAP 檔案系統即可。建立沙箱 Clone 需要代管（已註冊）的 SQL Server 以及操作和修復權限。

link:create-sandbox-clone.html["建立沙箱複製"]。

.對於沙盒 Clone，重新整理、重新基線和分割之間有什麼區別？
重新整理會將 Clone 同步到來源資料庫的目前狀態或先前的快照，並刪除您對 Clone 所做的任何變更。重新基線會將 Clone 還原到建立時的狀態，同樣會刪除變更，並且與建立新 Clone 相比，可以節省空間。分割會將 Clone 轉換為獨立的資料庫，使用儲存容量，並在分割完成後刪除 Clone。

* link:manage-clones.html["管理資料庫 Clone"]。
* link:split-clone.html["分割資料庫 Clone"]。


.如何驗證沙箱 Clone 的資料是否正確？如果檢查失敗該怎麼辦？
如果在來源資料庫繁忙時建立 Clone，則 Clone 可能與最新快照不同步。完整性檢查會檢查 Clone 中的所有物件。如果檢查失敗，請勿使用該 Clone，並建立一個新的 Clone。

link:manage-clones.html["檢查資料庫 Clone 的完整性"]。

.在分割 Clone 之前，我應該檢查什麼？
分割會建立一個新的資料庫，使用額外儲存容量。請提前規劃所需容量，並根據需要增加 FSx for ONTAP 檔案系統的容量。

link:split-clone.html["分割資料庫 Clone"]。



[[data-protection]]
== 資料保護

.Backup and Recovery 可為 SQL Server 工作負載提供哪些保護？
它使用本機快照在主要 FSx for ONTAP 儲存設備上備份工作負載，並使用 SnapMirror 技術將其複寫到次要 FSx for ONTAP 儲存設備。您可以在 Backup and Recovery 中建立保護原則。

link:protect-sql-server.html["使用備份和復原保護 SQL Server 工作負載"]。

.使用 NetApp Backup and Recovery 保護 SQL Server 需要哪些條件？
SQL Server 執行個體必須使用 Windows 認證資料註冊。您還必須符合 Backup and Recovery SQL Server 需求、NetApp Console 需求（包括 Console 代理程式）以及授權。Workload Factory 接著會安裝 Microsoft SQL Server 外掛程式，並將您重新導向至 Backup and Recovery 以建立保護原則。

link:protect-sql-server.html["使用備份和復原保護 SQL Server 工作負載"]。



[[automation-and-error-analysis]]
== 自動化與錯誤分析

.Codebox 是什麼？使用產生的程式碼時需要注意什麼？
Codebox 是一個基礎架構即程式碼輔助工具，可為 Workload Factory 支援的操作產生 REST API、AWS CLI、CloudFormation 和 Terraform 程式碼。Terraform 程式碼會隱藏 fsxadmin 和 vsadmin 密碼，因此您必須重新輸入這些密碼。下載或複製的 CloudFormation 範本僅保留七天。請參閱 link:automate-codebox.html["使用 Codebox 實現自動化"]。

.要使用人工智慧驅動的錯誤日誌分析器，我需要進行哪些設定？
分析器需要啟動 Amazon Bedrock、與主機子網路關聯的 Bedrock VPC 終端節點、已註冊的資源，以及所需的 IAM 權限。對於 Oracle，您還必須授予對 V$DIAG_ALERT_EXT 的存取權。如果您的帳戶系統管理員停用了 AI 功能，則無法使用分析器。

link:analyze-error-logs.html["了解如何在 Workload Factory 中分析錯誤日誌"]。

.使用錯誤日誌分析器時，我的日誌資料安全嗎？
日誌資料和聚合結果保留在您的 AWS 帳戶中，並透過私人 VPC 端點傳輸，不會暴露於公共網際網路。客戶資料不會用於訓練或改進模型。Bedrock 會即時處理日誌，並將結果儲存在您的環境中。
