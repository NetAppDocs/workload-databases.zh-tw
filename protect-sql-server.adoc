= 使用 Workload Factory for Databases 保護 Microsoft SQL Server 工作負載
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
從 Workload Factory 主控台使用 NetApp Backup and Recovery 保護您的 Microsoft SQL Server 應用程式資料。透過此整合，您可以在主要 Amazon FSx for NetApp ONTAP （FSx for ONTAP） 儲存設備上使用本機快照備份工作負載，並將工作負載複寫到次要 FSx for ONTAP 儲存設備。



[[about-this-task]]
== 關於這項工作

Workload Factory 可自動探索資源、驗證先決條件，並設定與安裝 Microsoft SQL Server 外掛，以準備使用 NetApp Backup and Recovery 來保護您的工作負載。該外掛是 NetApp 軟體的主機端元件，可讓您保護您的 Microsoft SQL Server 工作負載。

NetApp Backup and Recovery 使用 NetApp SnapMirror 資料複寫技術，透過建立快照複本並將其傳輸至備份位置，確保所有備份完全同步。

有關使用備份和恢復進行保護的詳細信息，請參閱 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["使用備份和復原保護 Microsoft SQL 工作負載概述"^]。



[[before-you-begin]]
== 開始之前

在使用 Backup and Recovery 保護 Microsoft SQL Server 工作負載之前，請符合這些要求。

* 確保您的環境滿足 link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#microsoft-sql-server-workload-requirements["備份和還原 SQL Server 要求"^]。
* link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#in-netapp-console["完成NetApp控制台要求"^]，包括設定、指派 IAM 角色，以及安裝 Console 代理程式。


如果您擁有NetApp帳戶的組織管理員存取權限，則 `backup and recovery super admin`當您<<使用NetApp Backup and Recovery 做好保護準備,使用NetApp Backup and Recovery 做好保護準備>>。

* 在主控台代理程式上設定主機解析
+
若要探索資料庫，您必須在主控台代理程式上設定主機解析。在託管裝置上，將 IP 位址到主機名稱的對應新增至  `/etc/hosts` 檔案。

+
** link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["設定NetApp Backup and Recovery 的許可"^]






[[prepare-for-protection-with-netapp-backup-and-recovery]]
== 使用NetApp Backup and Recovery 做好保護準備

完成準備過程，以使用NetApp備份和復原來保護您的 Microsoft SQL Server 資源。

.步驟
. 使用其中一項登link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["主控台體驗"^]入。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導航至儲存、EDA、AI、資料庫、VMware 和管理等工作負載。"] 然後選擇*資料庫*。
. 從資料庫選單中，選擇*Inventory*。
. 在清單中，選擇 *Microsoft SQL Server* 作為引擎類型。
. 找到您想要保護的實例，然後從選單中選擇*保護*。
. 如果出現提示，請提供具有管理存取權限的 Windows 憑證。
+
若要使用NetApp Backup and Recovery 進行保護，必須使用 Windows 憑證在 Workload Factory 中註冊 SQL Server 執行個體。

. 如果有多個控制台代理處於活動狀態且可用，請選擇要註冊和保護工作負載的「控制台代理」。
. 選取 *開始* 以準備資料保護。Workload Factory 會自動在 Backup and Recovery 中註冊您的 SQL Server 資源，設定並安裝 Microsoft SQL Server 外掛，並探索資源以符合保護 SQL Server 執行個體的先決條件。
. 滿足先決條件後，選取 *Redirect* 以存取 Backup and Recovery。


.下一步
從備份和復原中，建立一個原則來保護您的 Microsoft SQL Server 執行個體和資料庫。

link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-create.html["了解如何建立策略來保護您的 Microsoft SQL Server 執行個體和資料庫"^]。

相關信息，請參閱 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["備份和恢復文檔"^] 用於管理 Microsoft SQL Server 工作負載。



[[edit-protection-for-microsoft-sql-server-resources]]
== Microsoft SQL Server 資源的編輯保護

您可以編輯NetApp Backup and Recovery中已受保護的 Microsoft SQL Server 執行個體和資料庫的保護設定。編輯保護功能可讓您修改受保護 SQL Server 執行個體的保護原則或計畫。

. 使用其中一項登link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["主控台體驗"^]入。
. 選擇選單 image:workloads-menu-icon.png["漢堡選單圖示用於導航至儲存、EDA、AI、資料庫、VMware 和管理等工作負載。"] 然後選擇*資料庫*。
. 從資料庫選單中，選擇*Inventory*。
. 在清單中，選擇 *Microsoft SQL Server* 作為引擎類型。
. 選擇“*資料庫*”標籤。
. 找到要編輯保護的資料庫，然後從選單中選擇「編輯保護」。
+
您將被重新導向到NetApp Console中的「備份和還原」頁面，您可以在其中修改保護策略或計畫。
